# نشر الموقع على GitHub Pages 🌐

تحط النتيجة على موقعك المجاني على GitHub، والطالب يفتح لينك ويكتب رقم جلوسه.
**من غير سيرفر، من غير اشتراك شهري، ومن غير حد أقصى للزوار.**

---

## إزاي بيشتغل من غير سيرفر؟

GitHub Pages بيشغّل **صفحات ثابتة بس** — مفيش بايثون ولا قاعدة بيانات. يعني
`web.py` اللي في المشروع مش هيشتغل عليه.

الحل إننا **نقسّم النتيجة على ملفات صغيرة** حسب آخر ٣ أرقام في رقم الجلوس:

```
natiga/
├── index.html
└── data/
    ├── meta.json      ← أسماء المواد والمدارس والمحافظات (مرة واحدة)
    ├── 000.json       ← كل اللي رقم جلوسهم بينتهي بـ 000
    ├── 001.json
    └── ... 1000 ملف
```

الطالب لما يكتب `500001`، المتصفح بينزّل ملف `001.json` **بس** — حوالي ٧٠ كيلوبايت،
يعني أقل من صورة واحدة. مش بينزّل النتيجة كلها.

**مقاس على ٧٠٠ ألف طالب:**

| | |
|---|---|
| حجم الموقع كله | ~٦٦ ميجابايت |
| اللي الطالب بينزّله فعليًا | ~٧٠ كيلوبايت |
| وقت البناء | ~٢٨ ثانية |
| سرعة البحث | فوري |

## الخطوات

### ١. ابنِ الموقع

لازم تكون استوردت ملف النتيجة الأول (الخطوة ٥ في [دليل التشغيل](SETUP-AR.md)).

**ويندوز:** دبل كليك على `build-site.bat`
**ماك/لينكس:** `./build-site.sh`

```
✅ الموقع اتبنى في: .../privacy-policy/natiga
   • عدد الملفات: 1,000 ملف بيانات
   • أكبر ملف: 700 طالب (~69 كيلوبايت)
   • الحجم الكلي: 66.5 ميجابايت
```

هيتعمل فولدر اسمه **`natiga`** في جذر الريبو.

### ٢. جرّبه على جهازك الأول

من جوّه فولدر `natiga`:
```bash
python -m http.server 8000
```
وافتح `http://localhost:8000` — لازم يشتغل قبل ما ترفعه.

### ٣. ارفعه على GitHub

```bash
git add natiga
git commit -m "Publish results site"
git push
```

> ⚠️ الرفع أول مرة ممكن ياخد شوية لأن الحجم كبير. لو النت بطيء، سيبه يخلّص.

### ٤. فعّل GitHub Pages

1. افتح الريبو على GitHub → **Settings** → **Pages**
2. تحت **Source** اختار: **Deploy from a branch**
3. اختار الفرع (`main`) والفولدر `/ (root)` → **Save**
4. استنى دقيقة أو اتنين

اللينك بتاعك هيبقى:
```
https://ma01021402242-pixel.github.io/privacy-policy/natiga/
```

صفحة الـ Privacy Policy هتفضل شغالة زي ما هي على:
```
https://ma01021402242-pixel.github.io/privacy-policy/
```

### ٥. اربطه بالبوت (اختياري)

من BotFather: `/setdescription` وحط اللينك، أو حطه في رسالة `/start`.

## تحديث النتيجة بعدين

```
1. اسحب الملف الجديد على import.bat
2. دبل كليك على build-site.bat
3. git add natiga && git commit -m "Update results" && git push
```

## الموقع مقابل البوت — إيه الفرق؟

| | الموقع الثابت | البوت |
|---|---|---|
| التكلفة | مجاني تمامًا | مجاني على جهازك / ~٥$ على سيرفر |
| بيفضل شغال | دايمًا | لازم سيرفر شغال ٢٤ ساعة |
| البحث برقم الجلوس | ✅ | ✅ |
| البحث بالاسم | ❌ (محتاج سيرفر) | ✅ |
| الأوائل | ❌ | ✅ `/top` |
| بيتحمّل ضغط عالي | ✅ ممتاز | يعتمد على السيرفر |

**الأفضل: الاتنين مع بعض.** الموقع بيشيل الضغط الأكبر مجانًا، والبوت بيدي مميزات زيادة.

## حاجات لازم تعرفها ⚠️

**١. البيانات هتبقى قابلة للتحميل بالكامل.**
دي أهم نقطة. لما تحط الملفات على موقع ثابت، أي حد يقدر ينزّل الـ ١٠٠٠ ملف
كلهم ويطلع بقاعدة بيانات النتيجة كاملة. مفيش طريقة تمنع ده في الاستضافة
الثابتة — لأن الملفات نفسها هي اللي متاحة للمتصفح.

لو ده مقلقك، البدائل:
- **استخدم البوت أو `web.py` على سيرفر** — البيانات بتفضل عند السيرفر وفيه حد
  للطلبات لكل مستخدم
- **انشر بيانات أقل** — مثلًا من غير أسماء المدارس والإدارات

**٢. البحث بالاسم مقفول في النسخة الثابتة** — عشان يشتغل كان لازم المتصفح
ينزّل كل الأسماء. ده كويس للخصوصية وكويس للأداء.

**٣. حدود GitHub Pages:** الموقع لازم يكون أقل من ١ جيجا (إحنا عند ٦٦ ميجا)،
وفيه حد للاستهلاك الشهري ١٠٠ جيجا. بحساب ٧٠ كيلوبايت للزيارة، ده يكفي
حوالي **١.٤ مليون بحث في الشهر**.

**٤. الريبو هيكبر.** ٦٦ ميجا في الريبو عادي، بس لو حدّثت النتيجة كذا مرة،
كل نسخة بتتخزّن في تاريخ git. لو بقى تقيل، امسح `natiga` واعمله من الأول.

**٥. البيانات دي بيانات شخصية لطلبة أغلبهم قاصرين.** حتى لو النتيجة منشورة
رسميًا، نشرها في مكان يسهل تحميله بالكامل حاجة تانية. راجع شروط الجهة اللي
نشرت النتيجة قبل ما تعيد نشرها.

## مشاكل وحلولها

**الصفحة بتفتح بس مكتوب «مقدرتش أحمّل البيانات»**
فولدر `data` مااترفعش. اتأكد إن `git add natiga` شغل فعلًا، وإن الملفات ظاهرة
على GitHub.

**الصفحة مش ظاهرة خالص (404)**
- استنى دقيقتين بعد الـ push، النشر مش فوري
- اتأكد إن اللينك فيه `/natiga/` في آخره بالشرطة
- اتأكد من إعدادات Settings → Pages

**النشر بياخد وقت طويل أو بيفشل**
البناء بيحط ملف `.nojekyll` تلقائيًا عشان يمنع GitHub من معالجة الـ ١٠٠٠ ملف.
لو المشكلة موجودة، اعمل ملف فاضي اسمه `.nojekyll` في **جذر الريبو** كمان.

**عايز الموقع يبقى على الرابط الأساسي مش في فولدر**
غيّر مكان البناء وامسح صفحة الـ Privacy Policy أو انقلها:
```bash
./build-site.sh --out ..
```
